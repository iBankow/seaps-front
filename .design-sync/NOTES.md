# Re-sync notes — seaps-front

- **This repo is an app, not a published library.** `package.json` has no `main`/`module`/`exports`. The converter runs in synth-entry mode via `--entry ./src/.ds-entry-anchor.ts` and `cfg.srcDir: "src/components"` scopes discovery to `ui/` + `common/` + `layout/` only (excludes `src/features/*`, routes, hooks). **Critical: the `--entry` path must NOT exist on disk.** It only anchors `PKG_DIR` resolution by walking up from its dirname to find `package.json` — passing a real file (e.g. `./src/main.tsx`) makes the converter bundle THAT file directly as the real entry (pulling in the whole app + its CSS imports, which then fails on Tailwind/package-export resolution). Keep using `./src/.ds-entry-anchor.ts` (deliberately absent) on every re-sync.
- **Full re-sync command**: `node .ds-sync/resync.mjs --config .design-sync/config.json --node-modules ./node_modules --entry ./src/.ds-entry-anchor.ts --out ./ds-bundle --remote .design-sync/.cache/remote-sync.json` (fetch the remote anchor first via `DesignSync(get_file, path: "_ds_sync.json")`). Builds take a long time in this environment (observed 2–15 min per full build under system load) — background them and poll, don't assume a hang.
- **Authored preview scope (24 of 208 components) — the rest are floor cards, authorable incrementally**: `Button`, `Badge`(pre-existing), `Card`, `Dialog`, `AlertDialog`, `Table`, `DataTable`, `Select`, `Checkbox`, `RadioGroup`, `Switch`, `Tabs`, `Tooltip`, `Popover`, `DropdownMenu`, `Avatar`, `Progress`, `Toggle`, `Separator`, `Skeleton`, `Breadcrumb`, `Field`, `Input`, `Label`, `Chip`. Deliberately NOT authored: `Toaster` (needs an imperative `toast()` call to show anything — a static preview can't trigger it easily), `Form` (react-hook-form context, needs a real form setup), layout nav components (`SiteHeader`, `AppSidebar`, `NavMain`/`NavSecondary`/`NavUser`, `Breadcrumbs`) — coupled to TanStack Router/Query context, likely to need `cfg.provider` wiring or stub data to render standalone.
- **`cfg.cssEntry` is a content-hashed build asset** (`build/assets/index-<hash>.css`), not a stable path. Raw `src/styles.css` is unprocessed Tailwind v4 source with zero generated utility classes — copying it verbatim ships completely unstyled previews. Before every re-sync: run `npm run build`, find the new hashed CSS filename under `build/assets/`, and update `cfg.cssEntry` in `.design-sync/config.json` to match.
- **Critical ordering: `npm run build` must run AFTER authoring `.design-sync/previews/*.tsx`, not just once at the start.** Tailwind v4's automatic content scan covers the whole repo (minus `.gitignore`), which includes `.design-sync/previews/` — but only classes present in files AT BUILD TIME get compiled. Authoring a preview that uses a Tailwind class not already used elsewhere in the app's real `src/` (e.g. `h-20`) silently ships that one card unstyled if the CSS was captured before the class existed. Symptom: a specific utility looks broken/missing in exactly one card while everything else looks fine. Fix: re-run `npm run build`, grab the new hashed CSS filename, update `cfg.cssEntry`, rebuild the DS bundle, recapture, re-eyeball. Do this once after each wave of newly-authored previews, not just at setup.
- `npm run build` also runs `tsc`, which currently fails on 2 pre-existing unused-import errors in `src/routes/__root.tsx` (unrelated to this sync, part of the user's in-progress `fix/architecture` branch work). `vite build` itself (which produces the CSS/JS we need) succeeds before `tsc` runs, so this doesn't block the sync — just don't treat a nonzero `npm run build` exit as a sync failure without checking whether `build/assets/*.css` was actually produced.

## Known render warns

Triaged as legitimate — not fixed, not blocking upload:

- **`[TOKENS_MISSING]`**: `--header-height`, `--tw`, `--detail-medium-contrast`, `--text-high-contrast-rgb-value`, `--text-body` — referenced but not defined in shipped CSS. `--tw` is an internal Tailwind engine variable (harmless). The others are pre-existing gaps in the app's own `shadcn/tailwind.css` import, unrelated to this sync — not chased.
- **`[FONT_MISSING]` "source-code-pro"**: the `code { font-family: source-code-pro, ... }` fallback stack in `src/styles.css`. Minor, code blocks aren't part of the synced `ui`/`common`/`layout` scope. Accepted substitute (renders in a system monospace font).
- **`[RENDER_BLANK]` on ~30 structural sub-parts** (`AlertDialogFooter`, `AlertDialogHeader`, `AlertDialogMedia`, `AvatarGroupCount`, `BreadcrumbEllipsis`, `BreadcrumbItem`, `BreadcrumbSeparator`, `CardFooter`, `DialogFooter`, `DrawerFooter`, `DrawerHeader`, `DropdownMenuLabel`, `FieldSeparator`, `PaginationEllipsis`, `PaginationItem`, `PaginationLink`, `SelectGroup`, `SheetFooter`, `SheetHeader`, `SidebarFooter`, `SidebarGroup`, `SidebarGroupLabel`, `SidebarHeader`, `SidebarMenuItem`, `SidebarMenuSkeleton`, `SidebarMenuSub`, `SidebarMenuSubButton`, `SidebarMenuSubItem`, `SidebarProvider`, `TableCaption`, `TableCell`, `TableHead`, `Toggle`): these are compound sub-parts (flex wrappers with no default text content) — genuinely near-empty when rendered standalone with crash-prevention default props, not broken. They're outside the "core" preview-authoring scope; composing them with real content requires authoring their *parent* compound (Dialog, Card, Sidebar, Table, etc.), which doesn't fix their own standalone floor card. Authorable individually on a future re-sync if wanted.
- **Excluded via `componentSrcMap`**: `EmblaCarousel` (default export — `export *` never re-exports it, so it's unreachable on the bundle global by construction), `Pagination` (name collision: both `src/components/ui/pagination.tsx` and `src/components/common/pagination.tsx` export a component named `Pagination` — ESM silently resolves the ambiguous star-export to `undefined`; the `common` one is the app's data/meta-driven pagination component, the `ui` one is the shadcn nav primitive — kept the primitive's sub-parts, dropped the ambiguous root name), `CarouselButton` (app-specific: requires a real S3-backed `image` object shape and imports `@/config/env`'s `bucketUrl`, not a generic reusable primitive).

## Re-sync risks

- The pinned `cssEntry` hash goes stale on every rebuild — see above. A stale/missing path degrades silently to `[CSS_PLACEHOLDER]` or unstyled previews if not caught.
- Component scope (`src/components/ui|common|layout`) was a deliberate choice, not auto-detected — a future re-sync should keep this srcDir unless the user asks to widen/narrow scope.
- `synthEntry` mode means `.d.ts` prop types are auto-extracted from `.tsx` source via ts-morph, not from a real shipped `.d.ts` — weaker for components with complex generics; check `dtsPropsFor` overrides accumulate here if any component's extracted props look wrong.
